# Changelog

## 0.7.5

### Добавлено
- Иконка расширения в списке расширений: поток из трёх шагов на бирюзовом фоне, в стиле иконки расширения Jira. Исходник — `media/icon.svg`, PNG собирает `npm run icon`.

## 0.7.4

### Исправлено
- Решение тимлида, которое начинается со слова «тимлид» («тимлид, 20.10: вариант 1, …»), считалось незаполненным, если в нём нет «)», и расхождение висело стоппером. Заглушкой теперь считается только «тимлид» в скобках (`_(тимлид)_`, `(заполняет тимлид: …)`) или одно слово «тимлид».
- Обратная ошибка: заглушка `_(тимлид)_` с дописанным после неё текстом разработчика считалась решением. Теперь расхождение остаётся открытым.

## 0.7.3

### Добавлено
- Кнопка **«Обновить спеки»** — всегда в панели и иконкой в её заголовке: после подтверждения `git submodule update --init --remote <путь>`, сабмодуль спек до свежего main OpenSpec (раньше «Обновить спеки» было только при ненайденном change и без `--init`).
- Стопперы про устаревшие спеки: рабочая копия сабмодуля отстаёт от ветки (кнопка «Синхронизировать спеки»); файлы этого change в main OpenSpec новее закреплённых — решения по расхождениям, задачи, план (кнопка «Обновить спеки до main OpenSpec»); сабмодуль обновлён локально, а bump не закоммичен. Раньше в таких случаях панель молча показывала старые данные. `git fetch` сабмодуля — не чаще раза в 10 минут, «Обновить» сбрасывает.

## 0.7.2

### Изменено
- Стопперы объясняют, что делать: в каждом строка «Что сделать» с конкретным действием (какую кнопку нажать, кому передать, что дописать) и кнопка этого действия прямо в карточке — «Обновить change в OpenSpec», «Обновить плагин», «Подключить спеки», «Выбрать change», «Спроектировать и спланировать». Ссылка на файл называет его: «Открыть spec-gaps.md».
- Напоминание про `tasks.md` переформулировано: «Отметьте сданные задачи в OpenSpec: 2.1, 2.2, 2.3»; ссылка на `tasks.md` в сабмодуле убрана — его не правят.

## 0.7.1

### Исправлено
- «Плагин cex-sdd устарел» после обновления: если в проекте действует установка плагина для проекта (scope `project` или `local`), `claude plugin update` без `--scope` обновлял только установку для пользователя. Кнопка «Обновить плагин» теперь передаёт `--scope` установки, а подсказка объясняет, какая установка устарела.

## 0.7.0

Под плагин `cex-sdd` 0.7.0 и решение 20.10 по итогам пилота: правку change по spec-gap готовит лид скиллом `/cex-sdd:spec-update`, в PR кода — ссылка на неё.

### Изменено
- Кнопка «Предложить PR с правкой спеки» заменена на **«Обновить change в OpenSpec»**: она запускает `/cex-sdd:spec-update <change>` вместо собственного запроса расширения. Появляется только по решению «обновить change» без ссылки на правку или когда пора отметить задачи; открытые расхождения правку больше не предлагают. Команда `sddFlow.specPr` переименована в `sddFlow.specUpdate`.
- Ссылка на правку читается из «Решения» записи `spec-gaps.md` (`→ OpenSpec #N`, как пишет скилл) и из адреса PR в OpenSpec; поле «PR спеки» прежних записей тоже читается. Заглушка `_(тимлид)_` в «Решении» — расхождение открыто.
- Минимальная версия плагина `cex-sdd` — 0.7.0: в старых нет `/cex-sdd:spec-update`.

### Добавлено
- Напоминание отметить задачи своей группы в `tasks.md` OpenSpec, когда все шаги их раздела плана смержены: без отметок change не архивируется.
- **AI-ревью**: состояние «прохода 0» у PR текущей ветки (черновик, идёт, готово, без комментария, упало, не запускалось) со ссылками на комментарий и лог; кнопка «Запустить / Перезапустить AI-ревью» ставит метку `ai-review` заново. Только в репозиториях с `.github/workflows/ai-review.yml`.

## 0.6.1

### Исправлено
- Запуск `claude` в терминале, когда нет расширения Claude Code, на Windows: запрос экранируется под PowerShell (в том числе типографские апострофы), в cmd запускается `claude`, а запрос остаётся в буфере. Команды установки плагина склеиваются без `&&`, которого нет в Windows PowerShell 5.1.
- Обновления панели больше не накладываются: опрос, фокус окна и события файлов во время расчёта сводятся в один повтор, устаревший расчёт не перезаписывает свежий.

### Изменено
- Ответы `gh pr list` кэшируются на 2 минуты, а не запрашиваются каждые 30 секунд и при каждом фокусе окна. Кнопка «Обновить» сбрасывает кэш.

## 0.6.0

### Добавлено
- **PR с правкой спеки**: кнопка «Предложить PR с правкой спеки», когда в `spec-gaps.md` есть расхождение с нужной правкой спеки без PR. Запрос в Claude Code: правка change в отдельном клоне репозитория спек, проверки спек, push и PR — после подтверждения разработчика, ссылка — в поле «PR спеки». Сабмодуль спек только читается.
- В `spec-gaps.md` читаются поля «Правка спеки» и «PR спеки»; стоппер «решено обновить change, PR со спекой нет».
- **План в репозитории спек**: `design.md`, `plan.md` и `spec-gaps.md` из `openspec/changes/<change>/plans/<репозиторий>/`. Вариант — настройка `sddFlow.plansLocation`, `plans:` в `.cex-sdd.yaml` или наличие каталога в спеке; тег «план в спеке» в шапке, прогресс — с `plan.md` из `main` спек.
